# cpp-lesson-pdf · Reference-calibrated v1.3.2

## 何时启用

用户要求 C++ 信息学竞赛/基础语法教学讲义、课堂练习详解、家庭作业解题分析、原有讲义 PDF 的同风格续作或排版修订时使用。用户只要求逆向提取模板或修改 Skill 时，产出模板/Skill，不擅自编造题目或生成完整新教材。

## 执行前必读（按需逐层加载）

1. `references/MASTER-PROMPT.md`：课程内容生成总提示词。
2. `references/REVERSE-ENGINEERING.md`：对原 15 页 PDF 的页码级逆向证据及测量值。
3. `references/PDF-STYLE-GUIDE.md`：版式、配色和 LaTeX 组件规范。
4. `references/CODE-COMMENT-RULES.md`：**每题完整题解及中文核心注释强制标准**。
5. `references/DEEP-REASONING-STEPS.md`：八步解题分析、状态语义、执行时机、循环上下界、反例论证。
6. `references/VISUAL-DERIVATION-STANDARD.md`：按算法类型选择图形，规范初始/更新/结果三层状态表。
7. `references/TOPOSORT-TRACE-WORKFLOW.md`：拓扑排序队列/入度逐步图表，FIFO 语义及有环反例。
8. `references/QA-CHECKLIST.md`：编译、样例、推导数值和 PDF 逐页检验及拒收规则。

## 核心流程

### A. 阅读并核对输入

- 阅读用户全部已提供的相关知识点、源 PDF 页及代码；若 PDF 有图片/表格/图解，不能只依赖 OCR 或抽取的纯文本。
- 逐题建立题面核对清单（题号、名称、输入、输出、样例、范围、特殊约定），禁止臆造没有提供的数据。
- 若提供参考代码，**先分析原代码的执行逻辑与缺陷**，保留原算法和变量命名，必要的修复另行说明。
- 原始题面、样例、已有题解出现矛盾时，注明源文件页码及冲突，不能暗中修改或宣称通过评测。

### B. 制作教学内容

默认分两部分：

- `一、知识点讲解`：情境引入 → 准确定义 → 核心规则 → 算法步骤 → 图解/状态模拟 → 关键代码模块 → 易错点 → 复杂度/拓展。
- `二、课堂练习`：**每一道题**含题目名称与限制、题面、样例、状态定义、**八步解题步骤分析**、**有数据来源且逐格可核验的可视化推导**、代码映射、反例/边界、复杂度、完整 C++ 题解代码（核心关键注释）。
- 对 DP、树形背包、搜索、图论中有复杂依赖的题，要求“**初始状态 → 每步动作/候选计算 → 更新结果 → 最终状态**”，不能只有最终图。必须标明不合法/不可达候选及其原因；举例数据需区分原题样例和教学示意数据。复杂步骤应给出可计算的反例验证，而非笼统说倒序更安全。

课后作业可使用 `一、课后作业详解`，但不得省略每题完整代码。不要仅生成概念、截图或 `<MINTED>` 占位符来冒充代码。

### C. 根据原版式生成 PDF

- 统一保留 A4 纵向、单栏白底、宋体、蓝/青绿/赭橙层级；采用 `templates/lesson-style.sty` 与 `templates/diagram-styles.tex`。
- 原版的双色表格、输入输出双栏、蓝/绿/橙/红浅底说明框、无花哨封面和 TikZ 有向图按场景复用；不要全部强制铺满。
- **使用 `tcolorbox` + `minted`** 呈现含 UTF-8 中文注释的 C++ 代码，代码文件单独存放。代码区必须保持编辑器语法高亮，但**不显示左侧/右侧行号，也不预留行号槽位**。`minted` 在某些版本首遍编译显示 `<MINTED>`；必须至少编译两遍，提取 PDF 文本检查占位符确实消失。
- 没有 XeLaTeX 或 Pygments 时不得声称 PDF 代码已经成功渲染；可提供 `.tex` / `.cpp` 源文件并说明限制。

### D. 检验并交付

- 运行 `scripts/build.sh` 或 `scripts/build.ps1`；执行 `scripts/validate.py --pdf output/main.pdf --check-demo-code`。
- 对 DAG/拓扑题，运行 `python3 scripts/trace_toposort.py --markdown output/toposort-trace.md --latex output/toposort-tables.tex`，使用已验证的队列/入度状态生成分步图表。注意 FIFO 队列顺序**不等于字典序最小拓扑序**，有环时不能展示部分结果为完整排序。
- 对涉及 DP 原地合并的示意案例，先运行 `python3 scripts/trace_dp_merge.py --markdown output/merge-trace.md` 核对每一项状态更新；其他算法也应尽可能以小脚本或人工逐格复核。只要画了状态表，就必须核对它与代码一致。
- 在至少一种 PDF 渲染器下渲染全部页面，检查段落、标题、公式、表格、箭头、图形与代码框边界；对照原 PDF 的第 1 页（概念图/术语表）、第 5 页（双栏样例）、第 6 页（关键代码）、第 8 页（推导框）、第 14 页（图+状态表）。
- 编译 C++ 示例并在题意明确时比对给定样例；未经在线评测不得使用“已 AC”作为事实。
- 交付可下载 PDF 和必要时的源文件/ZIP，明确报告验证范围、异常及未验证内容。

## 优先级与边界

1. **用户源文件准确性 > 算法正确性 > 可见完整代码 > 清晰教学逻辑 > 视觉精度 > 压缩页数。**
2. 中文注释必须在最终 PDF 的代码块中可见，并非仅在外部文字解释里出现。
3. 编译成功不等于内容正确或视觉复刻成功。必须检查 PDF 文本和渲染图。
4. 用户要求“完全一致”时报告实际测量值，并将“风格高相似”与“逐页像素级一致”明确区分。
5. 包装中不携带用户原始 PDF、外部字体文件或密钥；保留从原 PDF 提炼的参数和可再生成示例。


## v1.3.2 用户明确指定的代码页排版覆盖规则（高优先级）

以下规则优先于历史参考 PDF 的原始样式测量，所有新生成讲义默认遵守：

1. **彻底删除“排版说明”板块**：最终面向学生的 PDF 不得出现标题为“排版说明”的说明框，也不得出现解释源码如何引入、代码颜色如何显示、代码是否与本地测试同源、PDF 如何渲染等制作过程元说明。代码标题后直接进入代码框，不插入此类说明段/说明框。
2. **C++ 代码不显示行号**：代码框左侧和右侧均不得显示 1、2、3……行号；不得启用 minted 的 `linenos`，不得启用 listings 的 `numbers=left/right`，不得保留空白行号槽或数字 gutter。
3. **保留代码可读性**：继续保留白底浅灰蓝边框、等宽字体、正常缩进、C++ 关键字/类型蓝色、中文核心注释绿色、字符串暖色；只移除行号及其占位宽度，不改变代码本身。
4. **验收**：PDF 文本检查不得出现“排版说明”；样式源文件检查不得出现启用行号的选项；逐页检查代码左侧无编号、无残留空白 gutter。
5. 如果用户明确要求在某份讲义中保留制作说明或行号，以该次明确要求为准；否则默认禁用。
