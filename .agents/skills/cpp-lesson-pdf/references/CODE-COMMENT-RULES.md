# C++ 代码块强制核心注释与渲染规范

1. 每一道课堂/课后练习必须有独立的完整 C++ 参考代码块，而不只是代码片段。代码应来自单独 `.cpp` 文件，供编译测试与 PDF 排版复用。
2. 在对应代码段内部添加中文注释，按题目适当覆盖状态/变量定义、初始化理由、关键转移/判断、边界处理、输出含义。基础语法题 2–5 个精准注释即可；中等算法题一般 5–12 个，复杂题更多。
3. 注释质量优先于数量。不要把 `cin>>x; // 输入x` 等显然语法机械翻译大量重复写入；应解释“为什么需要这个值/执行这个转移”。
4. 输入样例及原代码需要先审阅，不可为增加注释偷偷改算法。若为修复错误而修改，须先说明原因，再给出修改版。
5. 保留正常 C++ 编辑器语法色彩：关键字/类型蓝，注释绿，字符串暖色，变量和运算符深灰/黑，左侧浅灰行号。使用等宽 Latin Modern Mono；中文注释 CJK 字体回退。
6. 优先通过 `tcolorbox` + `minted` + Pygments `vs` 风格显示中文 UTF-8 代码，**至少两遍 XeLaTeX**。源码编译正确不代表 PDF 代码已经渲染。PDF 中不能出现 `<MINTED>` 字样。
7. 如果无法运行 minted 或 XeLaTeX，请先报告阻碍，不要删除中文注释，也不要交付只有“解题代码”标题没有实际代码的 PDF。
8. 逐题验证该代码块可提取 `#include`、`int main()` 或相应主体、关键中文注释、答案输出；并人工浏览代码所在页。

## 建议的 C++ 样例

```cpp
vector<int> indeg(n + 1, 0); // indeg[v]：v 尚未满足的前置条件数量
for (int i = 1; i <= n; ++i)
    if (indeg[i] == 0) q.push(i); // 零入度节点无需等待，可最先处理
while (!q.empty()) {
    int u = q.front(); q.pop();
    for (int v : g[u]) {
        // 处理完 u，u->v 这条先后约束就已满足
        if (--indeg[v] == 0) q.push(v);
    }
}
```
