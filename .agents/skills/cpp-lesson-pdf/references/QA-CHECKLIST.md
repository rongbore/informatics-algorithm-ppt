# 逐页 PDF / 算法 / 代码验收清单

## 输入源
- [ ] 已识别源文件全部题数、页数和题号
- [ ] 题目描述、输入、输出、样例、数据范围没有遗漏或凭空修改
- [ ] 发现矛盾时标注原文件页码，没有掩盖差异

## 算法与 C++
- [ ] 先审阅了用户的原有代码，未随意替换算法
- [ ] 每题输出**完整可编译 C++ 程序**，不是只给片段
- [ ] 中文核心注释位于程序内，且真正解释变量、初始化和算法步骤
- [ ] 样例已实际测试（如可执行）；无法测试时明确说明
- [ ] 复杂度和索引、溢出、重复边等边界与题目约束一致
- [ ] 未声称未证实的在线评测 AC

## PDF 视觉
- [ ] A4/正文坐标/字号与基准接近
- [ ] 原版蓝/青绿/赭橙标题层级准确
- [ ] 双色浅底提示框和图形适度使用
- [ ] 表格双栏、数学公式、箭头不压缩/重叠
- [ ] 代码框白底、行号、C++ 高亮、中文绿色注释在最终 PDF 可见
- [ ] 没有 `<MINTED>`、`<LISTINGS>`、占位符和丢字方块
- [ ] 所有页面经过渲染检查（至少一套 PDF 渲染器）
- [ ] 跨页代码没有截断，文末没有孤立或空白页

## 技术
- [ ] XeLaTeX 至少两遍编译，退出码 0
- [ ] 通过 `validate.py` 的结构、A4、代码注释与 placeholder 检查
- [ ] 代码 `g++ -std=c++17` 编译和给定样例核对通过（如适用）
- [ ] 文件包不包含字体文件、密钥、临时日志或用户原 PDF


## v1.3 解题分析与状态图专项验收（每道算法题）

- [ ] 先写清状态定义、下标含义、状态何时可用以及初始化原因。
- [ ] 关键循环**每一层**都说明变量意义、起止范围、迭代方向和合法性条件。
- [ ] 每个核心 `if` / `continue` 都写明它跳过的具体情况，标注不可达与负数收益等的区别。
- [ ] 推导表含“旧状态 → 候选计算 → 比较/判断 → 新状态”，实际更新、保留旧值和跳过原因均可追踪。
- [ ] 状态图数值与代码、样例/教学示意来源一致，明示“正式样例”或“构造示意”。
- [ ] 错误写法必须配可计算反例，说明错误从哪一步产生；对枚举方向的解释不作跨算法的错误泛化。
- [ ] 逐步输出能被程序或独立核算复现；复杂题不能只给未经核对的 AI 生成数据图。
- [ ] 图和表在 PDF 中无重叠、裁切、脱离解释文字，配色语义一致，黑白打印仍可理解。
- [ ] 逐步推导与最后完整 C++ 题解代码对应，包含可见中文核心注释。

## v1.3.1 拓扑排序与图论推导验收

- [ ] 验证有向图节点数、边列表及来源；可视化箭头不能反向或遗漏。
- [ ] 初始入度包含所有边（含重复边），队列只包含入度为零的节点。
- [ ] 每个节点出队及所有出边更新均被记录；入度从 1 变 0 才新增入队。
- [ ] FIFO 队列顺序与 C++ 代码一致；不要把 FIFO 输出宣称为最小字典序。
- [ ] 有环时处理顶点数少于 n，展示错误/剩余节点，不展示“完整”拓扑序。
- [ ] 生成 Markdown 与 LaTeX 长表来自同一脚本，核对几处关键中间值，图表逐页可读。
- [ ] `python3 scripts/trace_toposort.py --markdown output/toposort-trace.md --latex output/toposort-tables.tex` 和回归测试执行成功。
