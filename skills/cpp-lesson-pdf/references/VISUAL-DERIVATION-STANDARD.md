# 数据可视化推导规范 v1.3

## 目标

生成**可独立核算**的图表，而不是装饰性插画。每道适合推演的题至少包含一个与代码一致的可视化计算链：**输入/初始化 → 当前状态 → 本次操作 → 候选计算与判断 → 更新后状态 → 最终答案**。极简单一输出题可采用对照表代替复杂流程图；不得为了数量而强制绘图。

## 六类标准组件（按算法选择）

| 算法 | 优先图形 | 必须有的内容 |
|---|---|---|
| 语法、输入输出 | 表达式求值与输出对照表 | 变量值、计算值、预期输出、空格/换行 |
| 枚举、排序、双指针 | 数组格与移动标记 | 指针/索引、比较条件、交换前后 |
| 搜索、递归、树 | 节点图与递归栈帧 | 当前节点、父子关系、访问时序、返回值 |
| 图论、拓扑、BFS | 有向图 + 队列/入度表 | 当前队列、处理点、入度/距离变化 |
| DP/背包 | DP 格子 + 枚举转移表 | 状态语义、旧值、候选值、最优值、边界 |
| 图上的 DP/树形 DP | 依赖箭头 + 合并前后表 | 子问题完成时机、边权、合并顺序、费用计次 |

颜色规则：深蓝 `#22598D` 表示状态/主结构，青绿 `#18766E` 表示**已确认/新更新**，橙色 `#B4661D` 表示**当前操作/待比较候选**，红色 `#C64545` 表示**错误分支、越界、反例**。颜色不能单独承担意义，须有文字/箭头/标签，保证黑白打印可读。

## 表格结构

用三层信息，必要时拆多张表：

1. **初始状态表**：明确已有状态和值域（不可达记为 -INF / ∞ / ×，不能伪装成 0）。
2. **逐次更新表**：列推荐为“步骤 / 当前节点或 j / 枚举变量 k / 旧状态 / 候选计算 / 合法性或判断 / 更新后”。同一轮多个 k 应列出；跳过要写原因，不应悄悄丢掉。
3. **最终状态表**：列所有相关索引与结束值，突出变化的格子；答案从哪个格子取必须写出来。

以《解析.pdf》第 3 页的专门示意数据为例：旧 `f[u][0..2]=[0,5,8]`，新 `f[v][0..2]=[0,4,7]`，连接费 `w=2`。倒序合并得到 `f[u][0..4]=[0,5,8,10,13]`；`j=4,k=1` 被跳过，因为需要旧部分选 3 人且 `sz[u]=2`。`j=2` 的候选值 7 与 5 都不能超过原值 8。这只是**示意推演，不是题目正式样例**。

## 分镜式排版要求

- 多阶段算法优先“每一步一张状态小图 + 下方一行算式”，状态太多时选择**关键节点**，但不可以跳过影响正确性的中间状态；必要时附完整表。
- 节点与边 label 不重叠，重要操作用单一高亮，图例描述全部颜色意义。
- 表格数据使用等宽数字并右对齐；公式独立呈现并标注单位和来源；上下连续步骤保持节点位置、颜色含义、变量命名一致。
- 每个图注明“初始”“处理中”“完成”“错误演示”，避免学生混淆不同时间的状态。
- 如果 PDF 跨页，状态图和对应核心说明尽量同页；使用表格续页标头，避免代码标题和代码分离。
- 推荐 TikZ 绘制无损结构图、booktabs/tabularx 制作表格，状态数量多时可以从经过程序验证的 JSON 生成 LaTeX 表格，**不要手工随意填写不存在的中间值**。

## 可复现数据源与验收

1. 将示意或真实样例输入显式保存，注明“源 PDF 页码和原题样例”或“为说明算法构造的示意数据”。
2. 使用相同转移规则生成状态历史；可用 `scripts/trace_dp_merge.py` 验证树形背包案例。
3. 校验表格的起点、每次变化、跳过理由、最终输出与 C++ 代码一致；对错误写法给出反例，不能只展示错值。
4. 在 PDF 中检查图表文字可读、无裁切溢出、每个高亮有文字含义，图表结束后能回答“这一格的值从哪里来”。

## 写给生成模型的交付要求

**解题步骤分析**（每一段必须包含条件/原因）+ **数据可视化推导过程**（初始化、动作、更新、结果可核验）+ **关键代码映射**（从推导指向语句）+ **完整题解代码**（中文核心注释）。如果不能验证表格数字，应先检查或明确不确定，不能作为确定答案展示。
